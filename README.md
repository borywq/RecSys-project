# Learning Item and User Representations from Temporal Interaction Matrices and Tensors

Командный проект по курсу «Рекомендательные системы». Текущий этап: proposal.

**Команда:** [ФИО участника 1], [ФИО участника 2], [ФИО участника 3]

## Задача

По журналу событий `(user, item, timestamp)` и истории пользователя до момента `t` нужно ранжировать объекты для следующего взаимодействия.

Каждый объект описывается своей глобальной траекторией активности: бинарной строкой матрицы `X ∈ {0,1}^{N×K}`, где `X[i,k] = 1`, если в календарном интервале `k` с объектом было хотя бы одно взаимодействие. Из этой матрицы строятся представления объектов (усечённое SVD, временной энкодер, в расширении CP-разложение тензора по типам событий). Затем представления агрегируются по истории пользователя, и полученный вектор пользователя используется для ранжирования.

**Исследовательский вопрос:** содержат ли представления, выученные из матрицы «объект × время», информацию о следующем взаимодействии сверх популярности, и при каких свойствах данных эта информация проявляется.

## Метод

1. **Матрица активности.** Строится по событиям до границы `T0`. Используются бинарный и логарифмический (`log(1 + n)`) варианты.
2. **Представления объектов `z_i`:**
   - SVD: `z_i = (U_d Σ_d)[i]`, ранг `d < K`; отдельно вариант без первой компоненты, которая близка к общей активности объекта;
   - временной энкодер: одномерная CNN по строке `X`, обучаемая вместе с рекомендательной целью;
   - CP-разложение тензора «объект × время × тип события» (расширение).
3. **Temporal-pool.** Вектор пользователя — взвешенное с затуханием `exp(−γ(t − τ))` среднее векторов `P z_i` по последним `L` событиям. Скор кандидата:

   `s(u, j, t) = h_u(t)ᵀ P z_j + a·log(1 + n_j(<t)) + b·log(1 + c_j(t; w))`

   Слагаемое популярности общее для всех вариантов. Обучение — sampled softmax со 100 отрицательными примерами.
4. **SASRec+Pop с регуляризацией.** Добавляется штраф `λ/N · ‖E_ID − Z W‖²_F`, который приближает ID-векторы к проекции временных представлений.

## Гипотезы

| | Гипотеза | Сравнение |
|---|---|---|
| **H1** | Календарная структура активности полезна для предсказания следующего объекта | Temporal-pool с `Z`, с `Z_shuf` (перемешанные интервалы в каждой строке: ранняя популярность сохраняется, совпадения профилей разрушаются) и с `R` (случайная матрица той же нормы) |
| **H2** | Представления дополняют сильную последовательную модель | SASRec+Pop: `λ = 0` против `λ > 0` для `Z`, `Z_shuf` и `R` |
| **H3** | Полезность зависит от свойств данных | Ширина интервала, binary / log-count, группы по плотности и изменчивости профиля, домен |

## Протокол оценки

- **Разбиение по глобальной шкале** с общими для всех пользователей границами:

  | Период | Назначение |
  |---|---|
  | до `T0` | матрица `X`, представления, каталог `I0` |
  | `[T0, T1)` | обучающие цели |
  | `[T1, T2)` | валидация |
  | после `T2` | тест |

  Для RetailRocket предварительно 40/40/10/10 по длительности: префикс ≈55 дней, `K ≈ 55` (дневные интервалы) или `K ≈ 220` (шестичасовые), `d ∈ {16, 32}`. Окончательные границы фиксируются по EDA до сравнения моделей.
- **Порядок оценки:** параметры фиксированы, для каждого события сначала прогноз, затем обновление истории и счётчиков. События с одинаковым временем не видят друг друга.
- **Ранжирование по всему каталогу `I0`** без сэмплирования.
- **Цели вне `I0`** исключаются из основной метрики, их доля публикуется. Для них и для пользователей без истории применяется RecentPopular.
- **Метрики:** NDCG@10, Recall@10 с усреднением по пользователям. Для ключевых сравнений — 3 запуска и парный бутстреп по пользователям.
